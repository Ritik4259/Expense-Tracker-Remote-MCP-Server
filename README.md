# Expense Tracker Remote MCP Server

A lightweight remote [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) server for recording, querying, and summarizing expenses. The server is written in Python, uses [FastMCP](https://gofastmcp.com/) for its MCP interface, and stores data in a local SQLite database.

## Features

- Add expenses with a date, amount, category, subcategory, and note.
- List expenses for an inclusive date range.
- Summarize spending by category for a date range.
- Optionally filter summaries to a single category.
- Expose a JSON resource containing supported expense categories.
- Run locally or as an HTTP service for remote MCP clients and hosted deployments.

## Available MCP operations

### Tools

| Tool | Description | Parameters |
| --- | --- | --- |
| `add_expense` | Add an expense to the database. | `date`, `amount`, `category`, `subcategory` (optional), `note` (optional) |
| `list_expenses` | Return expenses within an inclusive date range. | `start_date`, `end_date` |
| `summarize` | Group expenses by category and calculate totals and counts. | `start_date`, `end_date`, `category` (optional) |

### Resource

- `expense:///categories` — JSON containing the available expense categories.

## Requirements

- Python 3.12 or newer
- [uv](https://docs.astral.sh/uv/) recommended for dependency and environment management

The project dependencies are declared in `pyproject.toml` and include `fastmcp` and `aiosqlite`.

## Run locally with uv

Clone the repository and install its dependencies:

```bash
git clone https://github.com/Ritik4259/Expense-Tracker-Remote-MCP-Server.git
cd Expense-Tracker-Remote-MCP-Server
uv sync
```

Start the HTTP MCP server:

```bash
uv run expense-tracker-remote-mcp
```

By default, the server listens on all interfaces at port `8000`:

```text
http://localhost:8000
```

To use another port, set the `PORT` environment variable:

```bash
PORT=9000 uv run expense-tracker-remote-mcp
```

The SQLite database is created automatically in the system temporary directory as `expenses.db`. The server initializes the database and creates the `expenses` table on startup.

## Connect from an MCP client

The server uses FastMCP's HTTP transport. Configure an MCP-compatible client with the HTTP URL where this server is running. For a local server, that URL is typically:

```text
http://localhost:8000
```

A generic client configuration may look like this:

```json
{
  "mcpServers": {
    "expense-tracker": {
      "url": "http://localhost:8000"
    }
  }
}
```

If your MCP client expects the Streamable HTTP endpoint explicitly, try:

```text
http://localhost:8000/mcp
```

Use the endpoint format required by the client or hosting platform you are using.

## Connect through Prefect Horizon

[Prefect Horizon](https://horizon.prefect.io/) is Prefect's hosted MCP gateway and governance layer. Use it to manage a deployed MCP server rather than treating the Horizon homepage itself as the expense server endpoint. citeturn0view0

1. Open [https://horizon.prefect.io/](https://horizon.prefect.io/) and sign in or create an account.
2. Create or select a Horizon project/workspace.
3. Deploy this repository as an HTTP MCP server. The service must run the package entry point:

   ```bash
   uv run expense-tracker-remote-mcp
   ```

4. Configure the deployment to listen on the platform-provided `PORT` value. The application already supports this through `PORT` and binds to `0.0.0.0`.
5. After deployment, copy the MCP server URL generated by Horizon. It will be a deployment-specific URL; do **not** use `https://horizon.prefect.io/` as the MCP server URL unless Horizon explicitly provides that URL for your deployment.
6. Add the generated deployment URL to your MCP client, for example:

   ```json
   {
     "mcpServers": {
       "expense-tracker": {
         "url": "https://<your-horizon-deployment-url>"
       }
     }
   }
   ```

7. Verify the connection by discovering the `add_expense`, `list_expenses`, and `summarize` tools, and by reading the `expense:///categories` resource.

> **Important:** The SQLite database is stored in the host's temporary directory. For a production deployment, confirm that the hosting environment provides persistent storage, or replace the SQLite storage layer with a managed database before relying on the server for durable records.

## Example tool inputs

Add an expense:

```json
{
  "date": "2026-09-19",
  "amount": 24.5,
  "category": "Food & Dining",
  "subcategory": "Lunch",
  "note": "Lunch with the team"
}
```

List expenses:

```json
{
  "start_date": "2026-09-01",
  "end_date": "2026-09-30"
}
```

Summarize one category:

```json
{
  "start_date": "2026-09-01",
  "end_date": "2026-09-30",
  "category": "Transportation"
}
```

## Development

Run the server directly from the package when needed:

```bash
uv run python -m expense_tracker_remote_mcp
```

Keep expense dates in `YYYY-MM-DD` format so SQLite's text-based date range queries sort correctly.
